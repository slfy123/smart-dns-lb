# 探针流量对接与调度

本程序直接读取 CF-Server-Monitor 的 `/api/servers`，不要求在线路机再部署代理。实际地址和服务器映射由管理员在面板配置。

## 操作顺序

1. 在“全局设置”填写探针基础地址，例如 `https://monitor.example.com`。受保护接口按需填写 Bearer 只读令牌。公开接口留空即可。只配置你希望程序读取的接口。
2. 保存后点击“探针服务器列表”，取得精确服务器 ID。每条线路编辑界面填写 `probe_server_id`；ID 未设置时才使用精确名称。同名服务器不进行名称匹配。
3. 带宽 `capacity_mbps` 可填，例如 100 代表 100 Mbps。程序不从探针当前速率推测套餐上限；剩余流量模式只展示该值。
4. 按用户需求选择 `TRAFFIC_REMAINING`（剩余流量分配），或 `TRAFFIC_AWARE`（流量与带宽综合分配），点击“同步探针”。检查周期已用、总额、重置日、当前带宽以及数据时间。
5. 供应商口径和探针设置不一致时，在节点编辑界面覆盖流量计费方向、额度和重置日。

## 字段约定

| 源字段 | 程序用途 |
| --- | --- |
| `id`、`name` | 精确映射服务器 |
| `traffic_limit` | 额度，源界面称 GB，内部使用 1024³ 字节，即本程序的 GiB |
| `net_rx_monthly` | 本计费周期接收字节 |
| `net_tx_monthly` | 本计费周期发送字节 |
| `traffic_calc_type` | `total` 双向相加、`ul` 发送、`dl` 接收、`max` 上下行取大值 |
| `reset_day` | 1–31 计费起始日，月末自动取该月最后一天；0 表示无周期日期 |
| `net_in_speed`、`net_out_speed` | B/s，乘 8 后换算 Mbps；带宽占用按上下行较大值计算 |
| `last_updated` | 报告时间，Unix 毫秒，判断新鲜度 |

源码对照：`https://github.com/huilang-me/CF-Server-Monitor/blob/main/src/utils/traffic.js` 及 `src/frontend/composables/useServerCardData.js`。不使用 `timestamp` 代替报告时间，不把 `ip_v4` 等存在性标记当作入口 IP，也不使用累计开机流量 `net_rx/net_tx` 代替计费周期数据。配额空值或 0 视为未限额。

月度计数的重置由探针负责。本程序只读指标，不修改供应商账单，也不自行清零远程计数。手动填写 reset_day_override 只影响进度权重计算，需保持与探针实际重置日一致。供应商使用十进制 GB 时，请先换算为 GiB（GB × 10⁹ ÷ 1024³）。

## 仅按剩余流量分配

选择 `TRAFFIC_REMAINING` 时，健康节点数据完整且新鲜，未触发额度停用阈值，且基础权重大于 0，其新 DNS 分配概率为：

`该节点剩余 GiB / 合格节点剩余 GiB 总和`

这是绝对剩余流量比例，不是各自套餐的剩余百分比。算法忽略带宽上限、实时带宽占用、重置日期和正数基础权重。公共归一化系数用于面板展示有效权重，不改变实际比例，也不做权重平滑或比例上下限截断。

例如两台都剩余 80 GiB，即使套餐总额和带宽相差很大，也得到相同权重。基础权重 0、禁用、维护和健康检查仍可剔除节点；达到额度停用阈值立即停止分配。若数据过期、缺少额度或套餐未限额，该节点退回配置的基础权重，因此数据异常期间不保证严格剩余流量比例。有效数据节点使用 `100 × 剩余 GiB / 有效剩余额度中位数`，使兜底权重处于相近尺度。

默认额度停用阈值为 99%，只作用于新 DNS 分配；现有连接继续产生流量。所有候选耗尽时返回 SERVFAIL。周期流量清零仍由探针执行，本程序下次同步后恢复分配。

## 流量与带宽综合权重

先筛选可用且启用的节点，优先使用 UP，全部正常节点缺失时才使用 DEGRADED。默认每秒后台更新一次有效权重，解析请求不访问探针、不触发权重平滑、不写数据库。

`有效权重目标 = 基础权重 × 周期进度系数 × 剩余额度系数 × 带宽容量系数 × 当前带宽余量系数`

- 剩余额度较多、计费周期使用进度落后的节点获得更高目标权重。
- 套餐带宽较高的节点适当增加权重；接近带宽占满的节点降低权重。
- 为减少抖动，正常情况下按 `0.7 × 原权重 + 0.3 × 目标权重` 平滑。额度触发阈值立即归零，不等待平滑。
- 额度默认到 99% 后停止该节点的新 DNS 分配，仅对 `TRAFFIC_AWARE` 生效。已存在连接仍会产生流量，可按需将阈值调低留出余量。
- 探针超过 `max_age_seconds` 或指标缺失时回到基础权重。已观察到的超额状态也随指标过期解除，这是明确的“监控故障继续服务”策略；若要求硬性流量限额，应同时使用供应商/转发服务的字节限额。
- 探针故障不改变 VLESS 健康状态，真实业务探测继续进行。没有合格节点时默认返回 SERVFAIL，不把已确认故障的全部节点重新发给用户。

这些因素是 DNS 查询概率的反馈调节，不是对每个连接的字节调度。单个大流量用户、递归 DNS 合并缓存和长连接都会造成实际占比偏移。建议从相同基础权重开始，观察 1–3 天探针进度，再调带宽、额度和基础权重。

## 兼容其他探针

其他监控可提供一个小型只读转换接口，返回以下结构；无需改调度器：

```json
{"servers":[{"id":"relay-1","name":"线路一","traffic_limit":"1000","traffic_calc_type":"total","net_rx_monthly":107374182400,"net_tx_monthly":107374182400,"net_in_speed":1000000,"net_out_speed":2000000,"reset_day":1,"last_updated":1793000000000}]}
```

实际接口需实时填写 `last_updated`。程序默认每 45 秒读取一次，最多接收 2 MB JSON，不跟随重定向。读令牌保存于服务器私有数据目录，状态 API 隐藏该字段，浏览器留空保存时保留原值。
